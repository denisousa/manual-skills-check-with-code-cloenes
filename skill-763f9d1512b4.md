# archon-plan-strategist

Use this skill for the Plan role. Plan reads Review/evidence/topology, drafts the next proof round, and emits human/Git/lane artifacts without editing Lean or executing Git.

## Required Skill Stack

- `archon-plan-strategist`
- `archon-context-tools`
- `archon-plan-lock`
- `archon-subagents` only for bounded read-only reports when explicitly dispatched.

Plan does not inherit `archon-lean4-base` or `archon-lean-mcp` by default. Plan consumes Lean evidence from Review and EvidenceIndex; it does not inspect Lean goals directly unless a future approved role contract explicitly changes that boundary.

## Required Inputs

- Latest `CampaignReviewReport`.
- `EvidenceIndex`.
- `CampaignTopology`.
- `ProofStructureIndex` as evidence, not scheduler.
- Authoritative target dependency DAG, declaration boundaries, file write conflicts, accepted targets, diagnostics, failed routes, and recoverable Owner sessions generated by Runtime.
- Accepted-proof memory, strategy memory, and human decisions.
- Protected surface summary.
- Runtime mode and required output paths.

## SOP

1. Read latest Review and evidence index.
2. Identify current frontier and blockers.
3. Read topology and active/parked/closed lanes.
4. Read ProofStructureIndex as evidence, not scheduler.
5. Query `plan.query_proof_memory` for each active target, then verify uncertain Mathlib names with read-only `lean.search` or `lean.hover_info`.
6. Generate multiple strategy families from verified evidence; archived warnings prohibit signature copying.
7. Decide the number of Owner Lanes, each `targetQueue`, `activeTarget`, deferred activation, checkpoint policy, and session continuation policy.
8. Preserve a compatible Owner session for strict dependency chains; parallelize only targets whose dependencies and write boundaries permit it.
   A continuation Owner retains accepted targets in `targetQueue`; `completedTargets` must be a subset of that queue, and `laneTargets` must exactly match its target order.
9. Remove duplicate or wasteful targets while keeping route history as evidence rather than a scheduler-level permanent ban.
10. Decide Git actions for Git Master without executing Git.
11. Decide Owner Lane work orders without editing Lean.
12. Run promotion preflight and deterministic Owner topology validation.
13. Emit human summary, Git Master plan, and lane plan through tools.

## Fixed Boundaries

- Do not edit Lean.
- Do not run Git.
- Do not output shell commands.
- Do not hand-write final JSON.
- Use plan-tools builders.
- Runtime DAG is authoritative evidence; Plan owns strategy/topology; Validator owns legality; Scheduler only executes the accepted Plan.
- `ownerScope=targetQueue`, `checkpointScope=activeTarget`, and `continuationPolicy=preserve_session` unless Plan gives evidence for a new route session.

## MCP Input/Output Contracts

### `plan.read_state`

- Input: `{ "reviewPath": "...", "evidenceIndexPath": "...", "proofStructureIndexPath": "...", "topologyPath": "..." }` with optional `root`.
- Output: `PlanStateBundle` with Review, topology, evidence index, proof index, and available state refs.
- Used for: loading a coherent planning snapshot.

### `plan.read_latest_review`

- Input: `{ "reviewPath": "..." }`.
- Output: latest `CampaignReviewReport`.
- Used for: making Review the first source Plan reads.

### `plan.read_campaign_topology`

- Input: `{ "topologyPath": "..." }`.
- Output: `CampaignTopology` with main/integration refs, lanes, branches, worktrees, and dirty/stale facts.
- Used for: deciding Git Master actions without executing Git.

### `plan.read_proof_structure_index`

- Input: `{ "proofStructureIndexPath": "..." }`.
- Output: `ProofStructureIndex` with nodes, remaining sorries, stale flags, and evidence ids.
- Used for: proof-structure evidence only; never direct scheduling authority.

### `plan.open_evidence`

- Input: `{ "evidenceIndexPath": "...", "evidenceId": "lane-report:lane-a:..." }`.
- Output: source artifact excerpt with path, commit/ref, hash, and cited fields.
- Used for: separating first-hand facts from agent narrative.

### `plan.add_strategy_family`

- Input: `{ "family": { "familyId": "...", "target": "...", "rationale": "...", "evidenceRefs": [], "failureSignal": "..." } }`.
- Output: schema-valid `StrategyFamilyDraft`.
- Used for: portfolio construction and diversity checks.

### `plan.add_lane`

- Input: `{ "planLanesPath": "..." | "planLanes": {...}, "lane": LaneWorkOrderDraft }`.
- Output: validated lane draft or rejection issues.
- Used for: preparing Lane Prover work without editing Lean.

### `plan.add_git_action`

- Input: `{ "gitPlanPath": "..." | "gitPlan": {...}, "action": typed topology action }`.
- Output: validated Git action draft.
- Used for: instructing Git Master runner without shell commands.

### `plan.check_promotion_candidate`

- Input: `{ "promotionCheckResultPath"?: "...", "candidateRef"?: "...", "targetRef"?: "...", "reviewArtifactPath"?: "...", "evidenceIndexPath"?: "...", "protectedSignatureManifestPath"?: "..." }`.
- Output: `PromotionPreflightResult`.
- Used for: allowing promote actions only after accepted preflight.

### `plan.validate_cross_artifacts`

- Input: `{ "human" | "humanPath", "git" | "gitPath", "lanes" | "lanesPath" }`.
- Output: `PlanCrossValidationResult` with consistency errors.
- Used for: preventing orphan lanes, missing Git actions, and stale refs.

### `plan.emit_all`

- Input: `{ "bootstrap": {...} }`, `{ "fromReview": {...} }`, or validated human/git/lane drafts plus optional `outputDir`.
- Output: `plan-human.json`, `plan-git-master.json`, and `plan-lanes.json`.
- Used for: package-owned artifact emission.

### `plan.read_strategy_memory`

- Input: `{ "memoryPath": "..." }`.
- Output: strategy memory artifact as stored on disk.
- Used for: carrying forward rejected routes and prior human decisions.

### `plan.query_proof_memory`

- Input: `{ "target": "...", "signature"?: "...", "limit"?: 5 }`; Host injects the frozen proof-memory path.
- Output: accepted or explicitly warned archived proofs ranked by exact target and theorem shape, including verified lemmas, commit/evidence refs, and warnings.
- Used for: reusing validated routes without treating an archived signature change as authority.

### `lean.search` / `lean.hover_info`

- Read-only semantic discovery against the project environment.
- Used for: verifying exact Mathlib declaration names and signatures before putting them in a Lane strategy.
- Plan may not call edit or multi-attempt proof tools.

### `plan.record_strategy_memory`

- Input: `{ "memoryPath"?: "...", "rejectedRoute"?: {...}, "humanDecision"?: {...} }`.
- Output: updated strategy memory artifact.
- Used for: carrying campaign learning across context resets.

## Plan Supporting SOP Sections

The sections below are inventory-visible contract sections. They define named Plan behaviors and declared tool boundaries. Runtime mode may only rely on the tools that are present in the current runtime tool inventory; declared-only sections remain contract-only until promoted into runtime handlers.

### modified-brainstorming

Use `plan.add_strategy_family` and `plan.validate_strategy_diversity`. Input includes route id, target, rationale, distinctness evidence, and success/failure signals. Output is accepted/rejected strategy diversity evidence.

### campaign-evidence-reader

Use `plan.read_latest_review`, `plan.open_evidence`, `plan.read_gate_result`, `plan.read_lane_report`, and `plan.record_evidence_conflict`. Inputs are evidence ids and campaign id; outputs are source excerpts or structured conflict reports.

### campaign-topology-reader

Use `plan.read_campaign_topology`, `plan.validate_topology_refs`, and `plan.read_worktree_status`. Inputs are campaign id and lane refs; outputs are topology facts and stale/dirty worktree issues.

### proof-structure-index-reader

Use `plan.read_proof_structure_index`, `plan.query_frontier`, `plan.open_proof_node`, and `plan.request_proof_index_refresh`. Inputs are campaign/round and node ids; outputs are frontier evidence or refresh requests.

### git-topology-planner

Use `plan.add_git_action`, `plan.check_promotion_candidate`, and `plan.validate_cross_artifacts`. Inputs are lane drafts and topology facts; outputs are typed Git Master actions.

### intervention-selector

Use `plan.select_intervention`. Input is target, Review finding, proof node, and topology state. Proof-round output is one of `informal_support`, `decomposition`, `reroute`, `continue_existing`, `merge_repair`, or `human_escalation`. `polish_handoff` belongs only to proof-complete promotion planning, never to an in-proof round.

### strategy-progress-critic

Use `plan.request_strategy_critique`, `plan.request_progress_critique`, and `plan.record_critique_response`. Inputs are recent Review reports and blocker fingerprints; outputs are close/retarget/challenge recommendations.

### mathlib-feasibility-advisor

Use `plan.query_proof_memory`, `lean.search`, and `lean.hover_info`. Inputs are target signatures, Review diagnostics, and accepted proof evidence; outputs are concrete, API-verified decomposition/reroute/informal-support recommendations.

### reference-informal-source-manager

Use `plan.read_reference_summary`, `plan.request_informal_support`, and `plan.attach_reference_to_lane`. Inputs are source ids and lane drafts; outputs are attached reference evidence.

### boundary-protected-surface-awareness

Use `plan.read_protected_surface` and `plan.validate_lane_boundaries`. Inputs are protected declarations and lane drafts; outputs are accepted lane boundaries or escalation issues.

### human-escalation-protocol

Use `plan.add_human_question` and `plan.emit_human_escalation`. Inputs are decision reason and options; outputs are structured human questions or a `HumanEscalationReport`.

### persistent-strategy-memory

Use `plan.read_strategy_memory`, `plan.record_strategy_memory`, `plan.record_rejected_route`, and `plan.record_human_decision`. Inputs are decisions and evidence refs; outputs are updated strategy memory.

## Artifacts Emitted

- `plan-human.json`
- `plan-git-master.json`
- `plan-lanes.json`
- `PlanCrossValidationResult`
- `StrategyMemory`
- optional `HumanEscalationReport`

## Success Condition

The three JSON outputs are schema-valid, cross-artifact validation accepts them, every lane has evidence/gate/report paths, and no Plan artifact requires Lean editing or Git execution by Plan.

## Blocked Condition

Missing latest Review, stale topology, missing evidence ids, stale ProofStructureIndex, rejected promotion preflight, or unresolved human decision blocks Plan.

## Runtime Vs Contract Behavior

Runtime mode requires real plan package/MCP builders and evidence reads. `contract_only` mode may inventory the contracts but must not claim plans were emitted.

## TOOL_UNAVAILABLE Policy

Unavailable Plan MCP tools emit `ToolUnavailableReport`. Plan must not hand-write final JSON as a fallback.

## Skill-Specific SOP

Plan emits three JSON outputs through tools only. The campaign topology is execution structure, while ProofStructureIndex is evidence not scheduler. There is no Lean edit and no Git execution in this role.
